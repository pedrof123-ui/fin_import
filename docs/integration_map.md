## 1. Repository Overview

Primary working directory: `/home/pedro/projects/fin_import2`

The project is a financial data pipeline and analysis system. It imports Alpha Vantage
financials, computes monthly valuation and quality metrics per ticker, stores everything
in DuckDB databases, and exposes a Jupyter notebook (`notebooks/fundamentals_alpha.ipynb`)
for factor research and live scoring.

## 4. Point-in-Time Risk Assessment (Phase 0 finding)

The current feature engine in `pe.py` uses `fiscal_date_ending <= month_end` as the
availability gate. This is conservative in that it does not use future earnings, but
there is no explicit filing-date or accepted-date column. Quarterly data published up
to 75 days after period-end may not be available on `month_end` for months immediately
following a quarter-end. Phase 1 must audit and add conservative lag rules.

Additional note: sector assignments in the notebook (Cell 2b) use the most recent
`company_overview` sector for all historical months. This is standard factor convention
but technically applies future sector classification to historical data.

## 5. Notebook Strategy Recommendation

**Recommendation: keep the notebook as the research and exploration interface; add
standalone Python modules for point-in-time logic, backtesting, and live scoring.**

Rationale:
- The notebook already works and contains well-structured research code.
- Cells 1–8 (data loading, EDA, feature construction) are exploration — keep in notebook.
- Cells 9–11 (model training, SHAP, walk-forward) should be wrapped by a script for
  reproducibility but need not be fully migrated unless Phase 8 requires it.
- Cell 13 (live scoring) is the main candidate for extraction into a standalone script
  (`scripts/score_live.py`) per Phase 8.
- No duplicate module structure should be created.
